# haithamzedan.com

Personal site that publishes the same facts twice: once as a page a person reads, once as structured data an agent queries. No framework, no build step for the site, no runtime dependencies.

Live at **[haithamzedan.com](https://haithamzedan.com)**.

## What this is

Most portfolios are HTML that an AI has to scrape and guess at. This one serves its content three ways from one source, so a person and an agent get the same answer:

- **HTML** at `/` for people. Bilingual Arabic/English, with a live "agent inspector" rail that shows the JSON behind what you're reading.
- **JSON** at `/api/*.json` for tooling. CORS-open, no auth, one file per section.
- **MCP** at `/mcp` for agents. Six tools over the Model Context Protocol, so an assistant can call `get_profile` or `search` instead of parsing a CV.

Two plain-text drops round it out: `llms.txt` (an index) and `llms-full.txt` (the whole profile as one document).

## How it works

`api/*.json` is the single source of truth. Everything else is generated from it or points at it:

```
api/*.json ─┬─> index.html      the human page; text is copied in, so it works without JS
            ├─> llms-full.txt    generated by build.mjs
            ├─> llms.txt         hand-written index that points back at the JSON
            └─> server.mjs       MCP server; reads the JSON at boot, serves it as tools
```

Because all four read the same JSON, the human page and the agent tools can't drift apart. If the HTML and the JSON ever disagree, the JSON wins.

## Repo layout

```
index.html            the site: bilingual AR/EN, live agent-inspector rail
api/                  the JSON endpoints, single source of truth
  profile.json          identity, summary, location, contact, availability
  experience.json       employment history
  projects.json         shipped products
  skills.json           skill groups and certifications
  education.json        degrees and academic record
  index.json            discovery index for the above
build.mjs             regenerates llms-full.txt from api/
server.mjs            MCP server: JSON-RPC over stdio + streamable HTTP, zero deps
llms.txt              index for agents
llms-full.txt         whole profile as one document (generated)
.well-known/mcp.json  MCP discovery manifest
robots.txt            explicitly allows named AI crawlers
sitemap.xml
_headers              CORS and cache rules for Cloudflare Pages
assets/               portrait in three sizes (560 / 280 / 96 px)
.github/workflows/    deploy to Cloudflare Pages on push to main
```

## The one rule

When you change a fact:

1. Edit the relevant file in `api/`.
2. Run `node build.mjs` to regenerate `llms-full.txt`.
3. Update the matching copy in `index.html` (the HTML holds its own text so the page works without JS).
4. Restart the MCP server if it's running: it reads `api/` at boot.

## Run it locally

The site is static, so any file server works:

```bash
npx serve          # or: python3 -m http.server 8000
```

Open the printed URL. Editing `api/*.json` and refreshing is the whole content loop. Regenerate the text drop after edits:

```bash
node build.mjs     # rewrites llms-full.txt from api/
```

## The MCP server

`server.mjs` exposes the profile as Model Context Protocol tools. Zero dependencies, Node 18+, JSON-RPC 2.0 over two transports:

```bash
node server.mjs                      # stdio, for a local MCP client
node server.mjs --http --port 8787   # streamable HTTP
```

| Tool | Returns |
| --- | --- |
| `get_profile` | Identity, summary, location, languages, contact, availability |
| `get_experience` | Employment history with highlights and stack per role |
| `list_projects` | Shipped products, one line each |
| `get_project` | Full detail on one project by id (`gas-express`, `rento-car`, `receipt-scanner`) |
| `get_skills` | Skill groups and certifications |
| `search` | Free-text search across the whole profile |

Prose fields take an optional `lang` of `en` or `ar`. Query the HTTP transport directly:

```bash
curl http://127.0.0.1:8787/mcp     # server info + tool names

curl -X POST http://127.0.0.1:8787/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

curl -X POST http://127.0.0.1:8787/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"search","arguments":{"query":"fraud"}}}'
```

## Deploy

Every push to `main` builds and deploys the static site to Cloudflare Pages through `.github/workflows/deploy.yml`: it regenerates `llms-full.txt`, copies the public files into `dist/`, and ships them with Wrangler. First-time setup (repo, Pages project, secrets, custom domain) is in **[DEPLOY.md](DEPLOY.md)**.

The MCP server is a live Node process and can't run on Pages, so `/mcp` returns 404 there. The site, the JSON, and the text drops all work without it. To put `/mcp` live, run `server.mjs` on any Node host (Render, Railway, Fly.io) or self-host the whole site on a VPS.

<details>
<summary>Self-hosting everything on a VPS (nginx + systemd)</summary>

Nginx server block:

```nginx
server {
    listen 443 ssl http2;
    server_name haithamzedan.com;

    root /var/www/haithamzedan.com;
    index index.html;

    # Agents need CORS to read the JSON from a browser context
    location /api/ {
        add_header Access-Control-Allow-Origin "*" always;
        add_header Cache-Control "public, max-age=3600";
        default_type application/json;
    }

    location = /llms.txt      { default_type text/plain; add_header Access-Control-Allow-Origin "*" always; }
    location = /llms-full.txt { default_type text/plain; add_header Access-Control-Allow-Origin "*" always; }

    location /.well-known/ {
        add_header Access-Control-Allow-Origin "*" always;
        default_type application/json;
    }

    # MCP server runs behind the same domain
    location /mcp {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 300s;
    }

    location / { try_files $uri $uri/ =404; }
}
```

Keep the MCP server alive with systemd, at `/etc/systemd/system/haitham-mcp.service`:

```ini
[Unit]
Description=Haitham Zedan MCP server
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/haithamzedan.com
ExecStart=/usr/bin/node server.mjs --http --port 8787
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now haitham-mcp
```

## Make it your own

Fork it, then:

- Replace `haithamzedan.com` throughout (`index.html`, `robots.txt`, `sitemap.xml`, `_headers`) with your domain.
- Rewrite `api/*.json` with your data, run `node build.mjs`, and mirror the text into `index.html`.
- Swap the portrait. `assets/` holds three sizes: 560 px (hero, via srcset), 280 px (mobile), 96 px (nav avatar and favicon). Replace all three at the same dimensions; the HTML references them by filename.
- Fill in the four certificate links in `index.html` (search for `CERT_URL_`) and the store URLs in `api/projects.json`, which ship as `null`. An agent can't cite what isn't there.
- Decide whether your email belongs in public JSON (`api/profile.json`, `llms.txt`). Scrapers will find it; an alias is the alternative.
- `Haitham_Zedan_CV.pdf` is git-ignored so the full CV stays out of the repo. Remove that line from `.gitignore` to commit it.

External links get `target="_blank" rel="noopener noreferrer"` added at runtime, keyed off `location.hostname`, so it keeps working after you change domains. In-page anchors and `mailto:` stay in the same tab.
